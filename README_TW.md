# Bili Extended

給官方 Bilibili Android App（`tv.danmaku.bili`）用的 LSPosed 模組。它修正 Bilibili 內建 IJK 播放器在高幀率與倍速播放時的微卡頓，讓你選擇影片詳情頁播放器的渲染器、解除倍速上限、在畫面上顯示實際的影音格式，並可自動挑選最佳音軌。不修改官方 APK，全部在執行期 Hook。

- 支援 Bilibili 9.13.0、9.17.0、9.18.0（原生 Hook 會核對 IJK 函式庫的特徵，對不上就不掛鉤；其他版本只有部分 Java 功能可用）。
- 需要能載入新版 Xposed API（libxposed **API 102**）模組的框架，例如 LSPosed 2.2.x；Android 7.0／API 24 以上。
- 寫給 Bilibili 播放器工程師的根因分析與修復指引：[docs/bilibili-fix-guide.md](docs/bilibili-fix-guide.md)；Media3 之外另外加的機制（相位鎖定、節奏鎖定等）與實測改善：[docs/beyond-media3.md](docs/beyond-media3.md)。

## 功能

所有設定都**在 Bilibili 裡改**，入口叫 **Bili Extended**，有三個位置：全螢幕播放時右側「更多設定」面板（「播放反饋」卡片最上方）、影片頁右上角 ⋮ 的底部選單，以及 Bilibili 的**設置**頁。

| 分組 | 設定 | 作用 |
|---|---|---|
| 流暢度 | **影片渲染器**（`Texture`／`Surface external`／`Surface`） | 影片詳情頁播放器使用哪一個渲染器。**建議 `Surface external`**：保留縮放、旋轉、截圖，又能讓每一幀帶上屏時間戳。 |
| 流暢度 | **Media3 Vsync**（預設開） | 照 Media3（ExoPlayer）的方式排程並帶時間戳釋放影片幀，涵蓋各種倍速：1x 提前約一個固定時間交出、倍速時以節奏鎖定挑幀、晚到的幀按規則跳過。 |
| 流暢度 | **距離預定上屏的門檻**（預設 33 ms） | 距離預定上屏還超過這個時間就先不交；1–50 ms。 |
| 流暢度 | **比聲音晚到多少毫秒允許丟幀**（預設 30 ms） | 比聲音晚超過這個時間才允許丟幀；1–50 ms。 |
| 流暢度 | **HDR 影片自動用 Surface**（預設開） | 播放 HDR 影片時自動改用直連 `Surface`，HDR 資訊直接送到顯示器（外部渲染器會把 HDR 轉成 SDR）。 |
| 流暢度 | **原生解析度輸出**（預設關；只在面板解析度高於 UI 的螢幕顯示） | 影片以面板原生解析度送到顯示硬體，其餘 UI 維持原尺寸。 |
| 倍速 | **高倍速（最高 10x）** | 解除播放核心的倍速上限，並在倍速選單最前面加入 2.5x～10x、最後面加入慢速 0.33x 與 0.25x。高幀率或 4K 影片的高倍速可能超出解碼器能力。 |
| 倍速 | **長按加速倍率** | 2–10x（每次 0.5x）；預設沿用 Bilibili 的 3x。 |
| 資訊浮層 | **fps 浮層** | 顯示 `On \| Avg 120fps \| 1%Low 83fps \| Surface Ext`：Media3 Vsync 狀態、平均 fps、1% low、渲染器。 |
| 資訊浮層 | **影音格式** | 解碼器確認的視訊格式與所選音訊格式（例如 `HEVC \| Hi-Res 96KHz`）。 |
| 資訊浮層 | **位置與字體大小** | 浮層的水平／垂直位置（橫向、直向各一組）與字體大小。 |
| 音訊 | **自動挑選最佳音質** | 有獨立 DASH 音軌時挑頻寬最高者。 |
| 頁面行為 | **直式 Story 影片改用一般影片頁** | 把 `bilibili://story` 連結改道到一般影片頁。 |

另外，模組預設停用 Bilibili 播放器內建的效能取樣：它和傳遞畫面通知的執行緒共用，每次取樣會讓畫面停住 80–144 ms（詳見修復指引 B.5）。

設定只存在 Bilibili 自己的資料夾（`files/bilisurfacebridge/settings.txt`）；模組 App 不保存任何設定。模組只寫入非敏感的狀態到 log，不讀取帳號資料、Cookie、影片網址或播放授權值。

## 安裝

1. 從 [GitHub Releases](https://github.com/XPRAMT/BiliExtended/releases) 下載並安裝模組 APK，在 LSPosed 啟用，作用域只勾 Bilibili。
2. 強制停止後重新開啟 Bilibili，播放一般影片，從播放器選單開啟 **Bili Extended** 調整設定。
3. 之後更新模組不必重啟 Bilibili：播放中直接安裝新版即可（熱重載）。

免 root 的 NPatch／LSPatch：1.4.0 以前的版本實測過；API 102 這一版尚未在兩者上測試。

## 評分標準

每一輪在全螢幕播放時用 root Perfetto 錄 15 秒，只看 SurfaceFlinger 上影片圖層的實際上屏時間。

- **分析區間**：影片圖層的上屏範圍，扣掉頭尾各 1.5 秒。
- **通過與否以穩定段為準**：起播 5 秒後的部分。暫停恢復後的起步過渡不列入判定。
- **錄製必須完整**：錄製涵蓋（SurfaceFlinger VSYNC 計數器的時間範圍）至少是錄製長度的 95%，且有 SurfaceFlinger 逐幀資料；不完整的輪次不採計、要修好重錄。

### 名詞

- **格**：面板的一次刷新（VSync）。R＝實測面板刷新率（每秒幾格），從 trace 的 VSYNC 計數器量，不用標稱值。
- **間隔**：相鄰兩張上屏畫面之間隔了幾格（四捨五入到整數格）。
- **F**：內容幀率 × 倍速，也就是每秒要顯示幾張不同的畫面。
- **實際播放速度視為等於請求倍率**：實測穩定段內「每張上屏畫面的內容時間戳」對「上屏時間」回歸的斜率，與請求倍率的偏差在 0.73% 以內（0.25x～2x，原廠與模組共 78 輪），所以容許值直接用 F，不再依各輪實測速度調整。
- **容許值每輪各算**：W 與 R 是該輪自己量到的，所以同一組合的原廠與模組（取的是不同輪）容許值可能不同。
- **W**：分析區間的長度（秒）。

### 三種情況

依 F 與 R 的比例分三種情況，各有自己的「通過」條件：

**1. 稀疏：R／F 接近整數 n（誤差 < 1%）**。例如 4K60 1x 每張停 2 格、1080p24 0.25x 每張停 20 格。

- **準時率**＝間隔剛好 n 格的次數 ÷ 全部間隔數。
- **多停**＝間隔大於 n 格的次數；**少停**＝間隔小於 n 格的次數。
- 因為 R／F 不會剛好等於 n，每隔一段時間必然要多停（或少停）一格才能跟上聲音，這是物理下限：
  - 容許多停 ＝ ⌈W ×（R − F × n）⌉ + 1（括號內為負時取 0，再加 1）
  - 容許少停 ＝ ⌈W ×（F × n − R）⌉（括號內為負時取 0）
- **通過**＝多停 ≤ 容許多停，且少停 ≤ 容許少停。準時率只用來看比例，不直接決定通過；低幀率的組合間隔數少（例如每秒 15 幀時 8 秒只有約 120 個間隔），一次多停就讓準時率掉近 1%。

**2. 稠密：F／R 接近整數 k ≥ 2**。例如 4K120 2x（每格前進 2 張）、1080p24 10x。

- **奇偶翻轉**＝相鄰兩張上屏畫面的內容編號奇偶性改變的次數（例如原本都挑偶數張，突然改挑奇數張）。本表的稠密組合都是每格 2 張（F ≈ 240）。
- **通過**＝奇偶翻轉 0 次。同一張多停一格（相位不變）是物理下限，允許。

**3. 非整數比例**：其他情況，例如 4K120 1.5x（每 2 格 3 張）、1080p30 3x。

- **節奏偏差**＝每張上屏畫面的實際位置，與理想等間隔直線的最大距離（先扣掉整體的固定速度差），單位是張或格。
- **通過**＝節奏偏差 ≤ 1。偏差達到 1 就是看得見的一次頓。

**一輪通過**＝穩定段（起播 5 秒後）在它所屬的情況下符合上述條件，且錄製完整。表中「結果（穩定段）」欄的通過／未通過就是這個判定。

## 測試成果

模組結果用 `Surface external` 渲染器，開著 fps 浮層與影音格式浮層；原廠結果關掉模組的播放相關功能（見下）、兩個浮層關閉。Bilibili 9.18.0，離線快取。**在效能模式下測試**：手機把 Bilibili 加入遊戲模式；平板把大核群（cpu4–6）的最低頻率固定在最高，每輪錄製前確認沒有被系統壓頻。每個組合跑 2–4 輪，原廠與模組各取最好的一輪（穩定段）。

- **內容幀／面板幀**：內容幀＝來源幀率 × 倍速，也就是每秒有幾張不同的畫面。超過面板刷新率時，面板每格只能顯示一張，括號內是面板能顯示的幀數，例如 `180（120）`；沒有括號表示面板能全部顯示。
- **實測幀率**：穩定段內影片層實際每秒上屏的新畫面數，取自 SurfaceFlinger 的上屏紀錄（張數 − 1）÷ 第一張到最後一張的時間。

- **手機**：Nubia NX809J（Snapdragon 8 Elite Gen 5，Android 16，面板實測 120.28 Hz）。原廠與模組都測了（原廠 23 組只有火花 0.333x 通過）。
- **平板**：小米平板 6 Pro（Snapdragon 8+ Gen 1，HyperOS／Android 15，面板 120 Hz）。原廠與模組都測了。
- **原廠**：把模組所有會改變播放的功能關掉（Media3 Vsync、效能取樣封鎖、外部渲染立即繪製、圖片佇列加深、渲染器選擇等），只留倍速設定、倍速上限解除與量測標記；渲染器是 Bilibili 自己的預設（外部渲染）。評分標準與模組相同。
